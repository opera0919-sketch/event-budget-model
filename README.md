# event-budget-model

증권사 이벤트의 참여·예산을 모델링한다. 두 모델이 공존한다.

| 모델 | 위치 | 역할 |
|---|---|---|
| 신청자·예산 예측 | `src/event_budget/` | 회차별 신청 고객 수와 소요 예산을 사전 추정 (`events/*.yaml` 명세 기반) |
| **리워드 구조 최적화** | `src/` | 연금 타사이전 이벤트의 **최적 리워드 지급구조**(구간·조건·수준)를 시뮬레이션으로 도출 |

아래는 **리워드 구조 최적화 모델**의 문서다.

## 개요

타사이전금액(순입금) 구간에 따라 리워드를 지급하는 이벤트를 대상으로, 가상 데이터를
생성하고 여러 리워드 구조를 30회 시뮬레이션해 후보안을 도출·검증한다.
코어는 표준 라이브러리만 사용하며(재현성·이식성), 엑셀/차트에만 `openpyxl`·`matplotlib`을
선택적으로 쓴다.

> 과거에 실제로 stale 문서가 발생했다. 모든 수치는 아래 산출물에서 확인할 것.

## 핵심 가정

| 항목 | 내용 |
|---|---|
| 예산(제세 포함) | 리워드 ≥ 5만원이면 예산 = `(리워드/0.78)*0.22 + 리워드` (제세 22% 그로스업). 고객 수령액은 리워드 그대로 |
| 수요반응(탄력성) | 비선형 로지스틱 S-커브. 소폭 하향엔 **sticky(비탄력)**, 대폭 하향 시 참여 급감. 현행 대비 정규화 |
| 구간내 분포 | 순입금 구간 내부는 하한(최소 기준) 쪽으로 쏠린 **triangular** 분포 |
| 배수 참여 보너스 | 배수 적용 시 수혜 고객 참여율 가산(1.5배 +3%, 2.0배 +5%) |
| 리워드 단위 | **1만원 단위**(전 구간), 구간별 **엄격 증가**. 당초 '>5만원은 5만원 단위'로 가정했으나 현행에 6만원 티어가 실재해 틀린 가정이었다 |
| 시뮬레이션 | 30회 반복(흥행 15 / 비흥행 15), 신청자 4,000~5,000명, 분포 진동 반영 |

## 설계 품질 게이트

총예산·매력도만으로는 드러나지 않는 결함을 `src/quality.py`가 계량한다.

| 지표 | 의미 | 상한 |
|---|---|---|
| 유효율 SD | 급간별 유효 리워드율(리워드/순입금)의 가중 표준편차. **고객별 유효율을 인원 가중 평균**한다(급간 평균 금액에 리워드를 적용하면 `reward(mean)≠mean(reward)` 편향이 생기고 자격 미달자가 섞인 급간이 통째로 빠진다) | `MAX_RATE_SD` |
| 티어 역진 폭 | 상위 티어 진입 시 유효율이 오히려 낮아지는 최대 폭 | 낮을수록 우수 |
| 경계 절벽 | 인접 티어 리워드 배율 | `MAX_TIER_JUMP` |
| 평탄구간 | 구간이 커져도 리워드가 그대로인 지점 | 금지(엄격 증가) |
| 사문화 티어 | 실표본이 도달하지 못하는 티어 | 0개 |
| **현행 대비 리워드** | 동일 순입금 고객이 받는 금액의 현행 대비 비율. **100만원 격자**로 검증한다(1천만원 격자는 좁은 구간의 하락을 평균에 묻는다) | `MIN_RATIO_VS_CURRENT` |

## 후보안

배수 폐지(직접구간 9단계) 3안과 배수 유지(현행 7단계) 1안을 병기해 비교한다.
정의는 [`src/cases.py`](src/cases.py), 실측 비교는
[`report/recommendation_ko.md`](report/recommendation_ko.md) §7~§8을 볼 것.

- **안1 매력도우선 / 안2 균형 / 안3 효율우선** — 목표 '현행 대비 최저 보장률'
  85% / 80% / 75%로 도출. 경계는 리워드 격자와 **현행 실효 경계**(배수 역산:
  3,333만·6,667만·1.333억·2억)에 맞춰, 특정 구간이 반토막 나는 일을 막았다.
- **A안 배수유지** — 구조 변경을 최소화한 대안. 계량 지표에서는 오히려 우세하나,
  그 우위 일부가 미검증 가정(배수 참여보너스 +3%)에서 나온다.


## 구조

```
config/simulation_config.py   # 분포·티어·배수·탄력성·시나리오·시드
src/reward_engine.py          # 리워드/예산(제세) 계산, 단위·단조 헬퍼
src/distribution.py           # 분포 진동 + 구간내 triangular/beta 샘플링
src/data_generator.py         # 30개 데이터셋 생성
src/demand_model.py           # 로지스틱 탄력성 + 배수 참여 보너스
src/simulation.py             # 케이스 평가·KPI(예산/ROI/CPA/평균이전/worst-case)
src/optimizer.py              # 2단계 탐색(coarse→top20→fine), 목표별 선정, Pareto
src/quality.py                # 설계 품질(유효율 일관성·역진·절벽·사문화 티어)
src/cases.py                  # 대표 리워드 케이스 + 추천 3안
src/report.py                 # CSV·마크다운 리포트·민감도
src/viz.py                    # Pareto 차트(matplotlib)
scripts/                      # 실행 스크립트
tests/                        # 단위 테스트
```

## 작업 이력

설계 판단 근거, 검증 게이트, 저지른 오류와 정정, 재현 시 주의점, 미해결 과제는
[`docs/SESSION_LOG.md`](docs/SESSION_LOG.md)에 정리되어 있다. 이어서 작업할 때 먼저 참조할 것.

## KPI 정의

- **예산**: 제세 포함 회사 부담액 · **효율**: 유치이전금액/예산(배)
- **CPA**: 예산/리워드 수령자 · **평균이전금액**: 유치이전금액/신청자
- **매력도지수**: 유치이전금액 vs 현행(%) · **worst-case 예산**: 30회 중 최대/최소

> 'ROI'는 쓰지 않는다. 유치 이전금액은 수익이 아니라 자산 유입액이므로
> `(유치−예산)/예산`을 수익률로 부르면 24,938% 같은 오해를 부르는 값이 된다.
> 의미가 정확한 **효율(배)**만 사용한다.
